# Automation Tool Setup: "Godmode" Comprehensive Vulnerability & Cloud Scanner

This document details the final proposed setup, architecture, and configuration for a Python-based automation tool designed for "godmode" effectiveness. It integrates **Nuclei**, **Jaeles**, reconnaissance tools, and cloud storage scanners (S3/GCP) to provide a highly automated, daily scanning solution with maximum coverage and minimal noise.

## 1. Prerequisites & Dependencies

To ensure the smooth operation of this automation tool, the following core components and their respective dependencies must be installed and properly configured on the host system:

| Component | Purpose | Path / Installation Command |
| :--- | :--- | :--- |
| **Python 3.x** | Primary language for script execution and orchestration | `sudo apt install python3` |
| **Go** | Required for installing Go-based tools | `sudo apt install golang` |
| **Nuclei** | Template-based vulnerability scanner | `/home/ubuntu/.pdtm/go/bin/nuclei` [1] |
| **Jaeles** | Signature-based web application scanner | `/home/ubuntu/go/bin/jaeles` [2] |
| **Subfinder** | Fast subdomain enumeration | `/home/ubuntu/.pdtm/go/bin/subfinder` [3] |
| **HTTPX** | Probing and validating active HTTP/HTTPS services | `/home/ubuntu/.pdtm/go/bin/httpx` [4] |
| **Katana** | Next-generation web crawling and spidering | `/home/ubuntu/.pdtm/go/bin/katana` [5] |
| **Amass** | In-depth DNS enumeration and mapping | `/home/ubuntu/go/bin/amass` [6] |
| **Gau / Waybackurls** | Historical and known URL discovery | `/home/ubuntu/go/bin/gau` / `/home/ubuntu/go/bin/waybackurls` [7] [8] |
| **FFUF** | Extremely fast web fuzzer | `/home/ubuntu/go/bin/ffuf` [9] |
| **S3Scanner** | Scanning and identifying open S3 buckets | `sudo pip3 install s3scanner` [10] |
| **CloudEnum** | Multi-cloud OSINT tool for S3, GCP, and Azure | `git clone https://github.com/initstring/cloud_enum.git` [11] |

### Python Libraries

The Python script will leverage several standard and third-party libraries:

* `subprocess`: Essential for executing external command-line tools and capturing their output.
* `json`: Utilized for parsing and processing the JSON output generated by the scanners.
* `argparse`: Provides a user-friendly interface for defining and parsing command-line arguments.
* `logging`: Implemented for comprehensive logging of scan progress, warnings, and errors.
* `PyYAML`: Used for advanced configuration management.
* `boto3` & `google-cloud-storage`: (Optional) For advanced, direct interaction with cloud storage APIs.

## 2. "Godmode" Scanning Strategy

To achieve maximum effectiveness, the tool follows a "godmode" strategy characterized by deep reconnaissance, intelligent filtering, and multi-stage execution.

### Effectiveness Principles

1. **Deep Reconnaissance**: Start with extensive subdomain and URL discovery to expand the attack surface as much as possible.
2. **Intelligent Filtering**: Use tools like **HTTPX** to filter out dead hosts and non-web services, ensuring that subsequent scanners focus only on viable targets.
3. **Context-Aware Scanning**: Dynamically adjust scan profiles based on the technology stack identified (e.g., using Nuclei's `-tech-detect` or Jaeles' technology-specific signatures).
4. **Cloud Storage Integration**: Automatically identify and test the security of associated S3 and GCP buckets discovered during the reconnaissance phase.
5. **Noise Reduction**: Implement deduplication and severity-based filtering to ensure that the final report contains only high-value, actionable findings.

## 3. Tool Architecture

The automation tool is designed with a modular architecture to promote maintainability, extensibility, and clear separation of concerns.

### Core Modules

1. **Orchestrator (`main.py`)**: The central control unit, managing the overall scan workflow and coordinating the activities of other modules.
2. **Tool Wrappers**:
   * `nuclei_wrapper.py`, `jaeles_wrapper.py`: Manage vulnerability scanners.
   * `recon_wrapper.py`: Handles Subfinder, Amass, Gau, and Waybackurls.
   * `discovery_wrapper.py`: Manages HTTPX and Katana.
   * `cloud_wrapper.py`: Integrates **S3Scanner** and **CloudEnum** for cloud storage security testing.
   * `fuzz_wrapper.py`: Integrates FFUF for targeted content discovery.
3. **Config Manager (`config_manager.py`)**: Responsible for loading, validating, and managing the tool's configuration settings.
4. **Data Processor (`data_processor.py`)**: Aggregates, filters, and normalizes findings from all integrated tools.
5. **Reporter (`reporter.py`)**: Generates a unified, human-readable report in specified formats.

### Execution Flow

The tool's execution follows a multi-stage sequence:

1. **Initialization**: Load configuration and verify tool paths.
2. **Reconnaissance Phase**:
   * **Subdomain & URL Discovery**: Use Subfinder, Amass, Gau, and Waybackurls.
   * **Cloud Bucket Discovery**: Use **CloudEnum** to find associated S3 and GCP buckets based on keywords and domain names.
3. **Asset Validation & Discovery Phase**:
   * **HTTP/HTTPS Probing**: Use HTTPX to identify active web services.
   * **Web Crawling**: Leverage Katana to discover hidden endpoints.
4. **Vulnerability & Cloud Scanning Phase**:
   * **Vulnerability Scanning**: Execute Nuclei and Jaeles against validated targets.
   * **Cloud Exposure Testing**: Use **S3Scanner** and **CloudEnum** to test the discovered buckets for public access and common misconfigurations.
5. **Data Aggregation & Normalization**: Collect, filter, and normalize all results.
6. **Reporting**: Generate a final, consolidated report.

Configuration settings will be managed through a `config.yaml` file:

  httpx:
    path: "/home/ubuntu/.pdtm/go/bin/httpx"

  amass:
    path: "/home/ubuntu/go/bin/amass"

    path: "/home/ubuntu/go/bin/gau"

    path: "/home/ubuntu/go/bin/waybackurls"

## 5. Scheduling

To enable daily execution, a cron job will be configured:

### Cron Job Setup

1. **Create a Shell Script (`run_scan.sh`)**:

   ```bash
   #!/bin/bash
   cd /path/to/your/automation_tool
   python3 main.py -l targets.txt --profile godmode
   ```

2. **Add to Crontab**:

   ```cron
   0 3 * * * /bin/bash /path/to/your/automation_tool/run_scan.sh >> /var/log/automation_scan.log 2>&1
   ```

This "godmode" setup and architecture provide a powerful, flexible, and highly automated solution for vulnerability and cloud storage scanning.
